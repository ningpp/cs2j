## linq-channel pass 第三轮性能优化（60s→19.5s 中位，输出与基线逐字节一致）

**目标**：用户要求 pass ≤20s，强制约束输出文件 md5 与基线一致。
**命令**：`dotnet run -c Release --project src/CSharpToJava.CLI/CSharpToJava.CLI.csproj -- preprocess -s D:/csharp-sdk/csharp-sdk.sln -d D:/cs/cs-linq-channel-perf --no-verify-build --no-verify-tests --pass linq-channel`

**结果**（多机况多次运行）：
- pass total：安静窗口 **18.61 / 19.48s**（稳定 <20s）；有后台负载时 20.3-21.4s（QQ 管家/Trae 抢核）；
  中位 ~19.5s。`dotnet run` 全命令 23.8s（含 ~2.3s 构建检查）。
- 基线（本轮前）：60.33s；最初串行：~108s。累计 ~3x / ~5x。
- 输出：代码树 1463 文件**逐文件 md5 一致** + 全树（含 obj）md5 `edb6eaa23f6afe11ab5dfb58d246eae2` 一致。
- 测试：LinqChannel/LinqRewrite/GotoEliminator/IteratorLowering/ClosureLift 285 项全过；ProjectTests --filter LinqChannel exit=0。

**剖析方法**：dotnet-trace 在重并行下开销 10x+（弃用）→ 临时 PerfProbe（Stopwatch 聚合 + Console.Error 分段），定位：
stage2 rewriter-visit 150s 线程（name-bind 91s=每 invocation 一次 GetSymbolInfo(memberAccess) 用于报告统计；classify 53s）；
residual 43s（统计被丢弃却全算）；iterator-lower：il-format 25s（final 全树 Format 病理）+ goto re-parse/Format 5.5s。

**保留的优化（全部 md5 验证）**：
1. **O2 语法预过滤**：非算子名（KnownOperatorNames∪{ForEach}）成员调用跳过 owner 查找；统计分支复刻 owner 门
   （字段初始化器无 owner 不记录 —— 曾因漏此门 +8 项 uncovered）。
2. **P2 residual 统计免算**：`ProcessFile(collectStatistics:false)` —— §7.10 幂等复检只用 RewriteChanged，
   Tally/EncounteredOperators 全跳；residual scanner 对非算子名且非 quoted 的 invocation 跳过分类。
3. **ns 预判**（gate.MayBeSystemBound）：classify 符号 ContainingNamespace 非 System → rewriter 的
   System.* 统计查询必然无记录 → 跳过（省 62% 调用）；**扩展方法保守必查**（reduced 符号渲染在 receiver 类型下，
   如 dotnet.xml 的 Task.IsSuccess 显示为 System.Threading.Tasks.Task.IsSuccess）；**classify null → 跳过**
   （两查询同 null，树上验证）。
4. **il/goto 格式化**：FormatSynthesized internal 化，块级并行（blocks+switch-sections，语句级 probe 独立 ——
   `previous=statement` 用原始语句）；语句循环串行（嵌套 Parallel 过度订阅反而慢）；GotoEliminator 节点级入口
   （Eliminate(root)）+ 复用 FormatSynthesized + lowering 输出树直通（FormattedRoot 免 re-parse）。
5. **closure-lift 分组并行**：按文件声明类型名并查集分组（保守超集），组间并行、组内文件序串行、每组独立
   ClosureLiftPreprocessor（命名表按 hostTypeKey 分桶，组间无共享 host → 与单表顺序跑等价）。
6. **restore 重叠**：context.Restore() Task.Run 提前至 lift/lowering 之前（restore 只碰 obj/，报告已落盘，
   诊断/verify/cleanup 在 await 后语义不变）。
7. 阶段计时走框架 context.Timings（desugar/compile/stage2/residual/closure-lift/iterator-lower/restore-verify）。
8. **符号级显示缓存**（LinqRewriter.DisplayStringBySymbol，ConcurrentDictionary + SymbolEqualityComparer）：
   同一合并编译下同一符号在数百调用点重复（Debug.Assert×1586）→ OriginalDefinition.ToDisplayString 每符号一次。
9. **stage1 解析复用 ParsedTreeCache**：prepare 的严格语法门已按源路径缓存全树解析（同签名），
   stage1 TryGet 命中后 WithFilePath(dest)（路径克隆，便宜）——desugar 1.0→0.5s。
10. **closure-lift 冲突键细化**：简单类型名 → 命名空间链+嵌套类型链（TypeChainKey）——语义 host 相等
    ⟹ 链键相等（保守方向成立），不同 ns 的同名类不再被串行化。

**被 md5 否决的尝试（等价性反例，勿重试）**：
- **P1 全名复用**：classify 的 GetSymbolInfo(invocation) 与 rewriter 的 GetSymbolInfo(invocation.Expression)
  会解析出**不同重载/不同形态**（扩展方法 reduced 渲染在 receiver 类型下）→ uncovered 名单漂移（12 项丢失）；
  非扩展限定版同样破（重载分歧真实存在）。rewriter 的名字查询必须自己执行。
- **span 限定 final Format**：全树 Format 对未注解源区域也做规范化（json/tests 差异）。
- **小块（阈值 1/2）chunk 化**：嵌套小列表（状态机 case 体 1-2 语句）的隔离格式化 separator 与全树不一致
  （XunitRunner/JsonDocumentTests 差异），且嵌套并行过度订阅更慢。
- **最深列表优先收集**：同上不等价。

**剩余瓶颈（20s 稳定达成的硬约束）**：
- `Regex.Groups.Tests.cs` 单文件 91KB→594KB（578 yield 的状态机），Roslyn Formatter 全树单线程 ~7s
  —— 等价约束下的下限（span/chunk 两种降法均破 md5）。
- stage2 ~7.4s：每 invocation 一次语义绑定是报告 `uncoveredOperators`（696 项，Debug.Assert×1586 等
  非 LINQ BCL 调用也在内）的 md5 必需 —— 若允许改报告口径可再砍 ~3s。
- 固定开销 ~4.5s（prepare/desugar/residual/closure/compile）。

**其它**：EnsureEnhancedReferences 仍注释（NEGATIVE-CHECK）；restore 在 --no-verify-* 下仍执行（obj 是
md5 的一部分，且喂 LC0050）。
