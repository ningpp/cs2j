## C# 类型形态空标记接口协议（推广 ref struct 的 implements 模式）

- 用户要求：把 `implements Cs2jByRefLikeMarker` 这种模式推广到 record / struct 等
  C# 有而 Java 没有的修饰符；硬性约束「不需要考虑当前实现，转换后只是实现一个空接口」。
  实现取纯增量路线：只加空接口与独立查询 Helper，**不改** `TypeHelper.getIsValueType`
  等现有查询语义（其注释记录了 548→547 的 nullable-struct 回归），零行为回归。
- 协议：`Cs2jTypeShapeMarker` 父接口 + `Cs2jStructMarker` / `Cs2jRecordMarker` /
  `Cs2jReadOnlyMarker`，`Cs2jByRefLikeMarker` 改为继承父接口。C# 侧在
  `src/Cs2jPrelude/CsPrelude.cs`（已有嵌入资源与工程引用），Java 侧在 compat 同名空接口，
  配置 4 条 typeMappings。compat 新增 `Cs2jTypeShape`（isStruct/isRecord/isReadOnly/
  isByRefLike/isMarked，全部 isAssignableFrom）。Java 转换器代码零改动。
- 新 pass `type-shape-marker`（默认启用，declarative，`runAfterIds: ref-struct-span-
  field-memory-lift`，位于 pointer-deref-index 之前、java-keywords 仍最后）：
  语义驱动给 StructDeclarationSyntax / RecordDeclarationSyntax 追加标记接口；
  跳过 static class、仍带 `ref` 的 struct、支撑库路径；保留已有 BaseList；幂等。
  注册改动：PassIds / PassCatalog / PassChainFactory / PassChainOrderTests.LockedChain
  与 legacy-toggle 排除列表（后两处必须同步，否则链顺序与覆盖测试红）。
- 不适用空接口的 C# 形态（C# 语言限制，已跳过）：`static class`（CS0713 不能实现接口）、
  `enum` / `delegate` / `interface`；`abstract` / `sealed` / `partial` Java 有对应或链已合并。
- 验证：C# 主测试项目全量 **4969 通过 / 0 失败 / 9 跳过**；compat 全量 **1755/0**；
  Cs2jPrelude 双 TFM 编译 0 错误；TypeMappings JSON OK。定向端到端：合成工程真实跑
  `--pass type-shape-marker` → `6 type(s) marked, 10 marker(s) added`，verify build 0 错误；
  单文件 Java 转换输出 `@CompatValueType public class PlainStruct implements Cs2jStructMarker,
  Cloneable` + `import io.github.ningpp.compat.Cs2jStructMarker;`。

## big-literal-resource：第 2 个预处理 pass（大数组/超长字符串外置为资源文件）

- 需求：`DemoBigBytes.cs`（大量 `byte[]`）、`DemoBigStrings.cs`（大量 `string[]` /
  超长字符串）超过 1MB 时既拖垮转换性能，也会让 Java 侧突破 `<clinit>` 64KB 方法体
  与常量池 65535 字节上限。用户指定该 pass 放**第二个**，紧随 `conditional`。
- 实现：`src/CSharpToJava.Core/BigLiteralResource/`（Options / Models / Extractor，
  纯语法、无 `SemanticModel`）。识别字段与局部变量的一维数组（元素类型
  byte/short/int/long/float/double/char/bool/string，且全部元素为字面量，可含
  `-`/`+`/数值 cast）与超长 `string` 字面量；载荷 ≥4096 字节才外置。
- 载荷格式：定长元素小端定宽槽位（byte/bool=1、short/char=2、int/float=4、
  long/double=8，整数字面量按二补码 64 位写后截断）、`string[]` 为
  「int32 小端字节数 + UTF-8」、`string` 整文件 UTF-8。
- 命名 `cs2j/<Owner>.<Member>.<sha256前8>.<bin|txt>`，物理落在声明文件同目录的
  `Cs2jResources/`；向宿主 csproj 追加 `<EmbeddedResource Include LogicalName>`
  （`LogicalName` 必须是**子元素**，`SolutionLoader.ScanProjectResources` 从
  `item.Elements()` 读；用 EmbeddedResource 而非 None+CopyToOutput 是为了避开
  SDK 默认 glob 的 NETSDK1022 重复项风险）。
- 运行时：`src/Cs2jPrelude/Cs2jResource.cs`（清单资源查找，双 TFM）经
  TypeMappings 映射到手写 `io.github.ningpp.compat.Cs2jResource`（**方法名必须
  camelCase**：转换器会把 `LoadBytes` 输出成 `loadBytes`）；资源和
  `Cs2jPrelude` 工程复用既有支撑库注入链路，ProjectReference 注入逻辑抽到
  `Preprocessing/SupportLibraryProjectReference.cs`（新 pass 用，老副本未动）。
- 保护：整棵树往返不逐字节相等就整文件不动；`const` 不处理（加载器调用不是常量）
  +CS2J4321；混排初始化器+CS2J4320(Info)；未配对代理项+CS2J4322；交错/多维、
  sbyte/ushort/uint/ulong 一律不动。诊断码 43xx（4301/4302/4303/4310/4320/4321/4322/4330）。
- 注册改动与 type-shape-marker 同款：PassIds / PassCatalog（物理紧随 Conditional）/
  PassChainFactory / PassChainOrderTests.LockedChain + legacy-toggle 排除列表。
- 实测（2.2MB 语料，`--no-verify-build --no-verify-tests`，全 56 pass）：
  **开启 28.7s vs `--disable-pass` 542.6s**，差额全在 `member-desugar`（487.1s → <1s）。
  源文件 1.17MB→744B、1.05MB→402B；C# 与 Java 两侧运行输出一致
  `bytes=180000 words=26000 sql=31798`，生成工程 `mvn compile` 通过。
- 验证：`tests/CSharpToJava.Tests` 全量 **4992 通过 / 0 失败 / 9 跳过**；
  `tests/CSharpToJava.ProjectTests --filter BigLiteralResourceCLITests` 4/4；
  `dotnet build CSharpToJavaConverter.slnx` 0 错误（8 个 CS8632 为既有支撑库告警）。
- 设计文档：`docs/superpowers/specs/2026-11-10-big-literal-resource-design.md`；
  README 的 pass 计数从过期的 42 修正为 56。
- 注意：该 pass 默认开启会改变含大数组/超长字符串语料的 Java 输出（资源文件 +
  加载器调用），全量 1986 个 .java 基线需要重新生成后才能逐字节比对。
