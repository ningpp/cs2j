## 设计层复盘：fc267008 为何走偏（用户质疑「preprocess 是为 Java 转换服务」）

- 统一中间树（本次 53 个 pass 的 intermediateDirectory 全是 `.cs2j-preprocessed-src`）
  同时喂两个消费者：C# .NET 预言机（dotnet test）与 Java 转换器。两者对 ref struct 要求相反。
- 直接压力：`PassCatalog` 中 ref-struct-lowering `verifyBuildByDefault/verifyTestsByDefault: true`，
  `RefStructLoweringPassAdapter.OnTestsFailed` 发 RSL010 Error → pass 判失败。作者 14:47/14:50
  的全量 dotnet build+test 复现 5 个失败，按 Agent.md「测试先行 + 语义等价」做了最小修复，
  并用 `RefStruct_UsedInTypeOf_IsPreserved_WithRSL001` 把「保留」固化为预期。
- 方向错误点：`ref` 是 C# 编译期约束，不是 Java 可翻译的语义载体。Java 侧复现
  `Type.IsByRefLike` 只能靠 compat 类型令牌/元数据；保留 ref 对 Java 输出零价值，
  只是把 C# 预言机保真成本转嫁给下游。
- 制度缺口（三处）：
  1. `PassCatalog.cs:751-760` 同时写 `Policy: ResidualPolicy.Fail` 与 `MayLeave: [RefStruct]`，
     注释称残留「expected, not a failure」，与 `ResidualContract.cs:11`（Fail=必须由 owner 消除）矛盾。
     设计文档 `docs/preprocessor-upgrade-plan.md:608` 给的正规出口是 `DeclaredUnsupported`。
  2. `normalization-audit` 仅在 `java-ready`/`audit` profile 追加（Program.cs:176/4246）；
     本次 `profile=default` 的 53 个 pass 无 audit，`RefStructResidualProbe`(Policy=Fail) 根本没跑。
  3. 设计文档 `docs/preprocessor-upgrade-plan.md:35` 已记录该 Known Gap：
     「链的成功标准是 C# 中间树可编译，不是 final tree 可 Java 转换；只有等到 Java 转换器逐类型抛错」。

## 用户硬性约束与最终方案（否决「让 Java 转换器处理」）

- **约束**：所有改写必须完全在 C#→C# preprocess 闭环；Java 转换器不得为 ref struct 加任何特判/放宽。
  允许在 java compat 补「对应映射」（Helper / 注解 / 接口）。上一轮方案 A 中「转换输入侧去 ref」的
  双树表述被否决，必须是单棵树同时满足 C# 预言机与 Java 可转换。
- 三个现成支点（已核实）：
  1. `TypeOperationTransformer.TypeOf:1044` 通用把 `typeof(X)` → `X.class`（TypeTokenLiteral），零特判。
  2. `java/.../TypeHelper.java:1990-1994` 已有 `getIsByRefLike(Class<?>)`（当前恒 false），
     转换产物 `dotnet-text-json/src/main/java/dotnet/text/json/JsonClassInfo.java:836` 正调用它。
  3. 原始 `json/src/.../JsonClassInfo.cs:556-575` 的 `#else` 分支本就用
     `IsByRefLikeAttribute` 的 FullName 判定（不读 CLR 标志）；条件编译 pass 才消成
     `type.IsByRefLike`（预处理树 `JsonClassInfo.Cache.cs:942-944`）。即用显式标记替代 CLR 标志有官方先例。
- **技术要害**：`Type.IsByRefLike` 是 CLR 只读标志，去 ref 后伪造不了 → 必须「声明侧去 ref + 打标记」
  与「消费侧 `.IsByRefLike` 改写为 Helper 查询」在同一次改写里一起做，否则 C# 预言机 5 用例必红。
  fc267008 只做了「保留声明」这一半。
- 推荐载体：标记接口（对比静态标记字段 / 类型级注解）。类型级 attribute→annotation 目前
  **无通用通路**（ClassTransformer/StructTransformer 没有，只有 PropertyTransformer:281 成员级硬编码），
  用注解会迫使改转换器，违反约束。
- 方案：扩展 ref-struct-lowering → `struct X : Cs2jByRefLikeMarker`（删 typeof 保留分支）；
  通用改写 `Type.IsByRefLike` → `Cs2jByRefLikeHelper.IsByRefLike(expr)`；
  `src/Cs2jPrelude/` 注入空接口 + Helper（支撑库不进 Java 转换，
  `NormalizationAuditPassAdapter:34` 已跳过）；`config/TypeMappings.json` 加接口映射；
  compat 加同名接口并把 `getIsByRefLike` 改为 `isAssignableFrom`。typeof 保持不动。
- 实施顺序（未开工）：失败测试 → Core 改写 → Prelude 注入 → compat/TypeMappings →
  dotnet test / java-ready 全链残差 0 / Java 转换 0 失败 / Maven 测试。单文件增量提交。
