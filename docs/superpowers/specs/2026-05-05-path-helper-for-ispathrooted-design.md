# PathHelper for System.IO.Path Static Methods

**Date:** 2026-05-05
**Status:** Approved

## Problem

`System.IO.Path` is mapped to `java.nio.file.Paths` at the class level in `TypeMappings.json`. When user code calls `Path.IsPathRooted(x)`, the converter emits `Paths.IsPathRooted(x)` — which is invalid Java because `java.nio.file.Paths` has no such method.

Only `GetTempPath` and `Combine` get special inline handling in `InvocationExpressionTransformer`. All other `Path` static methods fall through to broken Java.

## Solution

Generate a `PathHelper.java` compatibility class following the existing pattern used by `FileHelper`, `MathHelper`, `StringHelper`, etc., and remap `System.IO.Path` to it in `TypeMappings.json`.

## Files Changed

### 1. `src/CSharpToJava.Core/Pipeline/CompatibilityClassGenerator.cs`

Add `PathHelper.java` generation inside `GenerateUtilityClasses()`, after the `FileHelper` block (~line 1613).

### 2. `config/TypeMappings.json`

Replace the `System.IO.Path` entry (line ~1027):

**Before:**
```json

    "java": "Paths",
    "imports": ["java.nio.file.Paths"]
}
```

**After:**
```json

```

## PathHelper.java — Generated Methods

```java
package <basePackage>;

import java.nio.file.*;

/** Replacement for System.IO.Path static methods (generated by CSharpToJava converter). */
public class PathHelper {

    /** Mirrors Path.IsPathRooted */
    public static boolean isPathRooted(String path) {
        return path != null && Paths.get(path).isAbsolute();
    }

    /** Mirrors Path.GetFullPath */
    public static String getFullPath(String path) {
        return Paths.get(path).toAbsolutePath().normalize().toString();
    }

    /** Mirrors Path.GetDirectoryName — returns parent directory path, or null if no parent */
    public static String getDirectoryName(String path) {
        Path p = Paths.get(path).getParent();
        return p != null ? p.toString() : null;
    }

    /** Mirrors Path.GetFileName */
    public static String getFileName(String path) {
        Path p = Paths.get(path).getFileName();
        return p != null ? p.toString() : null;
    }

    /** Mirrors Path.GetFileNameWithoutExtension */
    public static String getFileNameWithoutExtension(String path) {
        String name = getFileName(path);
        if (name == null) return null;
        int dot = name.lastIndexOf('.');
        return dot > 0 ? name.substring(0, dot) : name;
    }
}
```

## Scope Boundaries

- **In scope:** Generate `PathHelper` with 5 methods, update type mapping
- **Out of scope:** Moving existing `Combine`/`GetTempPath` inline handlers to `PathHelper`, adding further `Path` methods (e.g., `ChangeExtension`, `GetExtension`)

## Existing Handlers — Unchanged

`GetTempPath` and `Combine` remain as inline conversions in `InvocationExpressionTransformer`. The class-level type mapping does not affect them because the transformer checks method names before falling through to the type mapping logic.
