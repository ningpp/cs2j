# UnsignedMath 改为独立 lib 项目 + compat 手写 Java 实现

日期：2026-09-24

## 1. 背景与问题

`unsigned-type` 预处理阶段（见 `2026-08-15-unsigned-math-helper-design.md`）的配套
辅助类 `_Cs2jUnsignedMath.cs` 现行机制：

- C# 内容来自 `UnsignedMathFileContent.Generate()`（巨型原始字符串常量）；
- 物理上在 `.cs2j-unsigned-src` 根目录写一份，每个实际编译了被改写源文件的项目
  通过 `<Compile Include Link>` 把同一物理文件编进自己的程序集
  （`internal static class`，每程序集一份）；
- 主转换时该文件又被每个 Maven 模块当普通源文件各自转换一遍：
  **N 个 csproj → N 份 `Cs2jUnsigned/UnsignedMath.java`**；
- `DiscoverImplicitModuleDependencies` 为此专门写了"共享包不建依赖"的特判。

问题：

- Java 输出中同一实现重复 N 份，且是从"可转换 C# 子集"翻译出来的保守实现
  （如 `DivideUInt64` 手写了 `Long.divideUnsigned` 的同款对折算法），不如直接
  调 JDK；
- 宿主项目的 `LangVersion` 必须 ≥ 11（helper 用了 `>>>`），把预处理阶段的
  语法要求泄漏给了用户项目；
- helper 源码活在字符串常量里，维护和测试都别扭。

## 2. 目标

- helper 成为一个真实的独立 C# lib 项目 X（`src/Cs2jUnsignedMath/`），
  `UnsignedMath.cs` 成为唯一真源，字符串常量退役；
- 转换时 N 个项目通过 `<ProjectReference>` 引用 X，不再各自编译 helper 源码；
- 主转换器把 X 仅当符号来源：不为其规划 Maven 模块、不转换其源文件；
- Java 侧在 `csharptojava-compat` 中提供手写的
  `io.github.ningpp.compat.UnsignedMath`（直接委托 JDK unsigned API），
  调用点经 `TypeMappings.json` 映射到该类；
- 生成的 N 个模块中不再出现任何 `Cs2jUnsigned` 包；生成模块已默认依赖
  compat，pom 零改动。

## 3. 非目标

- 不改 `UnsignedTypeRewriter` 的改写规则与调用形态
  （仍是全限定静态调用 `Cs2jUnsigned.UnsignedMath.XXX(...)`）；
- 不处理 TypeScript 路径（TS 转换不经过 unsigned 预处理）；
- 不把 `_Cs2jTupleTypes.cs` 等其他 `_Cs2j*` 支撑文件一并项目化
  （tuple 类型是按项目生成的内容，性质不同，留待单独评估）；
- 不解决 net40 等极老 TFM 引用问题（见 §9 已知限制）。

## 4. C# 侧：lib 项目 X

- 路径：`src/Cs2jUnsignedMath/Cs2jUnsignedMath.csproj`
  + `src/Cs2jUnsignedMath/UnsignedMath.cs`。
- `TargetFramework`：**`net10.0`**（与仓库 CLI/Core 一致，用户指定）。
- `LangVersion`：11（`>>>` 所需；项目自带，不再约束宿主项目）。
- `Nullable`：disable；`ImplicitUsings`：disable（源文件保持显式 using）。
- 源文件内容 = 现 `Generate()` 输出，仅两处调整：
  - `internal static class` → `public static class`（跨程序集可见）；
  - 顶部加 `// <auto-generated>` 之外的常规文件头注释说明其双用途。
- namespace 保持 `Cs2jUnsigned`、方法名与签名全部不变
  （调用点闭集由改写器生成，不动）。
- CLI 项目以 `EmbeddedResource`（`Link` 指向同一物理文件）嵌入
  `UnsignedMath.cs` 与 X 的 csproj 内容，运行时从资源释放——
  仓库真源、嵌入副本不会漂移。

## 5. 转换流水线改动

### 5.1 ProjectUnsignedTypePreprocessor

- `WriteExtensionFilesAsync` 重写：不再写根目录平文件；改为在
  `.cs2j-unsigned-src/Cs2jUnsignedMath/` 下释放 `Cs2jUnsignedMath.csproj`
  （来自嵌入资源）+ `UnsignedMath.cs`（来自嵌入资源）。
- `EnsureExtensionCompileItems`/`EnsureExtensionCompileItem` 改为
  `EnsureExtensionProjectReference`：给每个 host csproj（判定逻辑不变：
  实际编译了被改写源文件的项目）追加

  ```xml
  <ProjectReference Include="..\Cs2jUnsignedMath\Cs2jUnsignedMath.csproj" />
  ```

  同样先移除同名旧条目防重复。
- 删除 `UnsignedMathFileContent.cs`；在 CLI 侧新增一个小的静态类
  （如 `UnsignedMathSupportFiles`）负责从嵌入资源读取
  `UnsignedMath.cs` 与 csproj 内容并释放到目标路径。
- 后续流水线阶段（tuple/generic 等）是整树复制，X 目录随树存活；
  相对路径不变，ProjectReference 不失效。

### 5.2 主转换器与模块规划

- 工作区加载沿 ProjectReference 图自然加载 X，符号
  `Cs2jUnsigned.UnsignedMath` 对所有模块可见。
- `MultiModulePlanner`：按 csproj 文件名精确匹配
  `Cs2jUnsignedMath.csproj` 识别为支撑项目——不生成 PlannedModule，
  其被引用边不进入任何模块的 `CompileDependencies`（不出现在生成 pom 中）。
- 主转换器跳过对 X 项目源文件的转换
  （即旧设计文档 §4.3 预留的"跳过类定义"路线的落地）。
- 删除 `Program.cs` 中两处 Cs2jUnsigned 共享包特判
  （多模块共享包注释与 `DiscoverImplicitModuleDependencies` 的同名包豁免）。

### 5.3 单文件模式

`unsigned-type -i <file>` 语义不变：仍把一份 `_Cs2jUnsignedMath.cs`
写到输出文件同目录，内容改从嵌入资源读取（同一真源）。

## 6. Java 侧：compat 手写实现

### 6.1 类与包

- `java/csharptojava-compat/src/main/java/io/github/ningpp/compat/UnsignedMath.java`
  （包名 `io.github.ningpp.compat`，用户指定；类名不变）。
- 方法集合与 C# 版一一对应、同名、同参数个数
  （重载靠 paramCount 区分）；**方法签名必须与 `UnsignedTypeRewriter`
  生成的调用形态闭集逐一对齐**，实现计划阶段以改写器实际产出的调用清单
  逐一核对（特别是 `ToStringUInt32/64` 的 `IFormatProvider` 重载在 Java 侧
  的参数映射）。

### 6.2 实现委托关系

| 方法组 | Java 实现 |
| --- | --- |
| Int32/Int64 域 Add/Subtract/Multiply/位运算/LeftShift | 原生 int/long 运算（补码回绕语义与 C# unchecked 一致） |
| Divide/Remainder UInt32 | `Integer.divideUnsigned/remainderUnsigned` |
| Divide/Remainder UInt64 | `Long.divideUnsigned/remainderUnsigned` |
| CompareUInt32 / CompareUInt64 | `Integer.compareUnsigned` / `Long.compareUnsigned` |
| RightShiftUInt32 / RightShiftUInt64 | `>>>` |
| ToInt64UInt32 / ToUInt64UInt32 | `(long)(v & 0xFFFFFFFFL)` / `v & 0xFFFFFFFFL` |
| ToDouble/ToSingle/ToDecimal UInt64 | `Double.parseDouble(Long.toUnsignedString(v))` 等同路直写 |
| ToStringUInt32/64 各重载 | `Integer/Long.toUnsignedString`（带 provider 的重载按调用形态核对后实现） |

### 6.3 TypeMappings

- `config/TypeMappings.json` 增加类型级映射：
  `Cs2jUnsigned.UnsignedMath → io.github.ningpp.compat.UnsignedMath`。
- 方法名完全同名，预期只需类型映射；若 `MapMethod`（按
  containingType+name+paramCount）要求显式条目才能路由重载，则按调用闭集
  补齐方法条目。
- 转换后的调用点形态：import `io.github.ningpp.compat.UnsignedMath`，
  调用 `UnsignedMath.XXX(...)`。

## 7. 语义一致性

C# 版 helper 本就是 JDK unsigned API 的忠实移植（有
`UnsignedTypeSemanticsTests` 逐字节输出比对背书）；Java 手写版直接调 JDK，
两者对齐由 compat 新增 JUnit 单测保证：对每个公共方法在边界值
（0、1、MaxValue、MinValue 位模式、MaxValue/2、随机值）上与
`Integer/Long.compareUnsigned` 等 JDK 参考行为对拍。

## 8. 测试策略

- `UnsignedTypeProjectTests` 更新：中间树存在 `Cs2jUnsignedMath/` 项目；
  host csproj 含 ProjectReference、无 Compile Link；根目录无平文件；
  下游阶段（如 `.cs2j-tuple-src`）中 X 仍存活。
- `UnsignedTypeSemanticsTests` 更新：测试工程直接 ProjectReference
  `src/Cs2jUnsignedMath`（不再拼接字符串）。
- 端到端转换测试（多项目 sln）：各模块 `src/main/java` 下无
  `Cs2jUnsigned/UnsignedMath.java`；Maven 模块列表无 X；调用点带 compat
  import；产物可编译。
- compat 新增 `UnsignedMathTest`（JUnit 5，边界值对拍）。

## 9. 已知限制与风险

- **TypeMappings 覆盖面**：调用形态是改写器生成的封闭集合
  （全限定静态调用、无 using、无扩展接收者、无泛型），风险可控，
  由端到端测试兜底；若发现映射缺口，按闭集补条目。
- **TFM**：X 为 net10.0，宿主项目目标低于 net10.0 时引用会失败
  （现状 Compile Link 无此问题）。记录为已知限制；用户 sln 均为现代
  TFM 时无影响，遇到再议多目标。
- **名称碰撞**：用户 sln 已有名为 `Cs2jUnsignedMath` 的项目时会被误识别
  为支撑项目。概率极低，按 `_Cs2j*` 契约文档化。
- **阶段复制假设**：依赖"后续预处理阶段整树复制"保持 X 存活，
  实现计划需核实各阶段复制方式确实保留未改动文件。

## 10. 迁移

- 需要重新构建/安装 `csharptojava-compat`（本地 `mvn install`）后，
  新转换产物才能编译；对既有已生成代码无追溯影响。
- 本设计落地后，`2026-08-15` 设计文档 §4.1 的"Link 共享"与 §4.3 的
  "整文件转换"描述由本文档取代。
