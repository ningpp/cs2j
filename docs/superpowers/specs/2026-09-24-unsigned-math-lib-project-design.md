# UnsignedMath 改为独立 lib 项目 + compat 手写 Java 实现

日期：2026-09-24（修订版 2，吸收审查报告 L-1…N-5 共 28 条意见）

全文统一命名：lib 项目名为 `Cs2jUnsignedMath`（不再使用占位符"X"）。

## 1. 背景与问题

`unsigned-type` 预处理阶段（见 `2026-08-15-unsigned-math-helper-design.md`）的配套
辅助类 `_Cs2jUnsignedMath.cs` 现行机制：

- C# 内容来自 `UnsignedMathFileContent.Generate()`（巨型原始字符串常量）；
- 物理上在 `.cs2j-unsigned-src` 根目录写一份，每个实际编译了被改写源文件的项目
  通过 `<Compile Include Link>` 把同一物理文件编进自己的程序集
  （`internal static class`，每程序集一份）；
- 主转换时该文件又被每个 Maven 模块当普通源文件各自转换一遍：
  **N 个 csproj → N 份 `Cs2jUnsigned/UnsignedMath.java`**；
- `DiscoverImplicitModuleDependencies` 为此在注释中把 Cs2jUnsigned 列为
  共享包示例。

问题：

- Java 输出中同一实现重复 N 份，且是从"可转换 C# 子集"翻译出来的保守实现
  （如 `DivideUInt64` 手写了 `Long.divideUnsigned` 的同款对折算法），不如直接
  调 JDK；
- 宿主项目的 `LangVersion` 必须 ≥ 11（helper 用了 `>>>`），把预处理阶段的
  语法要求泄漏给了用户项目；
- helper 源码活在字符串常量里，维护和测试都别扭。

## 2. 目标

- helper 成为一个真实的独立 C# lib 项目 `Cs2jUnsignedMath`（
  `src/Cs2jUnsignedMath/`），`UnsignedMath.cs` 成为唯一真源，字符串常量退役；
- 转换时 N 个项目通过 `<ProjectReference>` 引用 `Cs2jUnsignedMath`，
  不再各自编译 helper 源码；
- 主转换器把 `Cs2jUnsignedMath` 仅当符号来源：不为其规划 Maven 模块、
  不转换其源文件；
- Java 侧在 `csharptojava-compat` 中提供手写的
  `io.github.ningpp.compat.UnsignedMath`（直接委托 JDK unsigned API），
  调用点经 `TypeMappings.json` 映射到该类；
- 生成的 N 个模块中不再出现任何 `Cs2jUnsigned` 包；生成模块已默认依赖
  compat，pom 零改动。

## 3. 非目标

- 不改 `UnsignedTypeRewriter` 的改写规则与调用形态
  （仍是全限定静态调用 `Cs2jUnsigned.UnsignedMath.XXX(...)`）；
- 不处理 TypeScript 路径（TS 转换不经过 unsigned 预处理）；
- 不把 `_Cs2jTupleTypes.cs` 等其他 `_Cs2j*` 支撑文件一并项目化
  （tuple 类型是按项目生成的内容，性质不同，留待单独评估）；
- 不解决宿主 TFM 低于 net10.0 的引用兼容问题（见 §9 已知限制）。

## 4. C# 侧：lib 项目 `Cs2jUnsignedMath`

- 路径：`src/Cs2jUnsignedMath/Cs2jUnsignedMath.csproj`
  + `src/Cs2jUnsignedMath/UnsignedMath.cs`；加入
  `CSharpToJavaConverter.slnx`（IDE 导航与 `dotnet build` 全仓验证需要；
  嵌入资源 `Link` 只要求文件存在，不引入构建顺序问题）。
- `TargetFramework`：**`net10.0`**。已核对主链全部 csproj 确认一致
  （CLI/Core/两个测试工程均 net10.0；仅 tools/WpfReflection 两个 Windows
  反射工具为 net6.0-windows，与本项目无关）。
- `LangVersion`：11（`>>>` 所需；项目自带，不再约束宿主项目）。
- `Nullable`：disable；`ImplicitUsings`：disable（源文件保持显式 using）。
- `src/Cs2jUnsignedMath/UnsignedMath.cs` 的内容 = 现 `Generate()` 输出的
  类定义部分，仅两处调整：
  - `internal static class` → `public static class`。现行 `internal` 源于
    "每程序集编译一份副本"的旧机制；`Cs2jUnsignedMath` 成为独立程序集后，
    host 只能经引用访问类型，故必须 `public`（与 `InternalsVisibleTo` 无关）。
  - 文件头注释：`UnsignedMath.cs` 顶部添加常规文件头注释（不使用
    `<auto-generated>` 标记），说明该文件既是仓库源码、又被 CLI 以
    EmbeddedResource 嵌入分发。
- namespace 保持 `Cs2jUnsigned`、方法名与签名全部不变
  （调用点闭集由改写器生成，不动）。
- 分发机制（本仓库首次使用 `EmbeddedResource`）：CLI csproj 以
  `<EmbeddedResource Include="..\Cs2jUnsignedMath\UnsignedMath.cs" Link="...">`
  嵌入，`Cs2jUnsignedMath.csproj` 内容同样以 Link 嵌入。机制上嵌入资源在
  构建期从 `src/Cs2jUnsignedMath/` 的同一物理文件读取，结构上不存在第二份
  副本可漂移。取舍说明：config 文件（`TypeMappings.json` 等）走 `Content`
  复制到输出目录，因其用户可见可改；helper 属内部支撑产物，嵌入分发不依赖
  安装布局，故选 EmbeddedResource。

## 5. 转换流水线改动

### 5.1 ProjectUnsignedTypePreprocessor

- `WriteExtensionFilesAsync` 重写：不再写根目录平文件；改为在
  `intermediateRoot/Cs2jUnsignedMath/`（即 `.cs2j-unsigned-src/Cs2jUnsignedMath/`，
  根名来自 `IntermediateDirectoryName` 常量）下释放
  `Cs2jUnsignedMath.csproj` 与 `UnsignedMath.cs`（均来自嵌入资源）。
- `EnsureExtensionCompileItems`/`EnsureExtensionCompileItem` 改为
  `EnsureExtensionProjectReference`：给每个 host csproj（判定逻辑不变：
  实际编译了被改写源文件的项目）追加

  ```xml
  <ProjectReference Include="..." />
  ```

  `Include` 相对路径按
  `Path.GetRelativePath(hostProjectDir, intermediateRoot/Cs2jUnsignedMath/Cs2jUnsignedMath.csproj)`
  动态计算（host csproj 镜像原树任意深度，硬编码 `..\` 只对一级子目录
  成立）。同样先移除同名旧条目防重复。**不**采用"复制
  `Cs2jUnsignedMath` 到每个 host 同级"的替代方案——ProjectReference 支持
  任意相对深度，保持单份即保持唯一真源。
- **host 位于中间树根的特判保留**：现有早返逻辑（SDK 项目且未禁用默认
  编译项、且项目目录与中间树根相同则早返）须有新版替代。新布局下若 host
  csproj 本身位于中间树根，`Cs2jUnsignedMath/*.cs` 会落入 host 的
  `**/*.cs` 默认 glob，导致 host 多编一份 helper；若 host
  `LangVersion < 11`，`>>>` 直接编译失败——§1 的"LangVersion 泄漏"问题
  在该场景原样回归。处理：检测到该场景时显式在 host csproj 排除
  `Cs2jUnsignedMath/**`（或告警并跳过 ProjectReference 注入），不得删旧
  特判而无替代。
- `UnsignedMathFileContent.cs`（Core 工程
  `src/CSharpToJava.Core/UnsignedTypeRewriter/`）随 CLI 侧新的静态类
  `UnsignedMathSupportFiles`（负责从嵌入资源读取两份内容并释放到目标路径）
  落地一并删除。删除前其全部 5 处引用点均在本设计改造范围内：
  CLI `ProjectUnsignedTypePreprocessor.cs:322/323/437/458`、
  `Program.cs:3724/3725`、`UnsignedTypeRewriterUnitTests.cs:32/536`、
  `UnsignedTypeSemanticsTests.cs:46`。
- **名称碰撞 fail-fast**：释放入口处显式检测用户解决方案中是否已含名为
  `Cs2jUnsignedMath.csproj` 的项目，命中即报错终止（不静默误识别）。
  契约已增补至 2026-08-15 文档 §4.3（保留项目名）。
- `--force` 重建整删 `intermediateRoot`（`Directory.Delete` recursive），
  `Cs2jUnsignedMath` 及其 `obj`/`bin` 构建中间产物随之清除，无残留缓存。
- 后续流水线阶段（tuple/generic 等）为**逐文件全树复制**
  （`EnumerateSourceFiles` 全树枚举、未变更文件也 `File.Copy`），
  `Cs2jUnsignedMath` 目录随树存活，相对路径不变，ProjectReference 不失效。
  附带两点：① `Cs2jUnsignedMath.csproj` 会流经各阶段 csproj 重写管线，
  需验证为 no-op；② 若用户构建过中间树，`Cs2jUnsignedMath` 的 `obj/bin`
  也会被复制到下游（冗余无害，建议复制层忽略）。

### 5.2 主转换器与模块规划

- 图加载：`ProjectDiscovery.LoadRecursive` 沿 ProjectReference 递归加载，
  `Cs2jUnsignedMath` 经注入的引用边自然进图，**无需改用户 sln**。
- 模块规划：`MultiModulePlanner.Build()` 现按
  `Kind == ProjectKind.Production` 过滤（`MultiModulePlanner.cs:33-35`），
  **新增**按 csproj 文件名 `Cs2jUnsignedMath.csproj` 精确匹配的 filter
  （置于拓扑排序之后、模块命名之前）。两个利好：①
  `Cs2jUnsignedMath` 不进 `moduleByProject` 后，host→它的引用边在
  `:62-68` 的 `TryGetValue` 处自然落空，`CompileDependencies` 无需任何
  删除逻辑，生成的 pom 不出现该依赖；② `ProjectKind` 枚举无需扩展。
- 主转换器跳过对 `Cs2jUnsignedMath` 项目源文件的转换
  （2026-08-15 文档 §4.3"跳过类定义"契约的项目级落地）。
- 注释更新而非删逻辑：`Program.cs` 全文 `Cs2jUnsigned` 仅出现 2 处且均在
  注释里（`:3274-3275`、`:3371-3372`）。只更新这两处注释中的 Cs2jUnsigned
  示例（该包消失后示例失效）；`DiscoverImplicitModuleDependencies` 的
  "本模块自声明包则跳过依赖"豁免是**通用机制**（真实受益者还包括
  system-private-uri / system-text-json 等共享包模块），与 Cs2jUnsigned 无
  字符串耦合，**保留不动**。
- 前置验证（实现计划第一批任务）：主转换的 workspace/Roslyn 符号解析若走
  sln 驱动加载，`Cs2jUnsignedMath` 不在中间树 sln 中时符号可见性需核实；
  fallback 为图加载后显式补载该项目的 compilation。

### 5.3 单文件模式

`unsigned-type -i <file>` 语义不变：

- 有 `-o` 时仍把一份 `_Cs2jUnsignedMath.cs` 写到输出文件同目录；无 `-o`
  时仅 stdout 输出、不落盘（现状行为，均不变）。
- 文件名与项目模式的 `UnsignedMath.cs` **不同名是有意的**：单文件产物保留
  `_Cs2j*` 支撑文件前缀契约（下游按前缀识别）；内容改从嵌入资源读取，
  即 public 版真源（`internal`→`public` 对单文件自包含场景无影响）。
- 该模式不释放 csproj：产物是改写后 C# 源 + helper 源码，后续编译由用户
  自行完成（本模式本就不产出工程）。

## 6. Java 侧：compat 手写实现

### 6.1 类与包

- `java/csharptojava-compat/src/main/java/io/github/ningpp/compat/UnsignedMath.java`
  （包名 `io.github.ningpp.compat`，用户指定；类名不变）。
- 边界说明：`UnsignedMath` 仅服务改写调用点的静态数学运算，不承担 compat
  已有 `UInt`/`ULong`/`UIntPtr` 的类型替换职责，两者并存。
- 实现口径裁决：**按 C# 版方法全集实现**（对称、防改写器未来扩展时 Java 侧
  缺位）、**按改写器调用闭集验收**（§6.2 清单即验收基线，同时作为该类
  public API 基线，后续重构以清单为准）。C# 版中改写器从不调用的
  `NotInt32`、`LeftShiftInt32`、`RightShiftInt32`、`CompareInt32` 四个方法
  也在全集口径内照常实现。
- 签名对齐：方法签名与 C# 版同名、同参数个数；带 `IFormatProvider` 的
  ToString 重载，Java 侧参数映射需与 C# 版"provider 被忽略、恒用
  `InvariantCulture`"的语义对拍；`(v, string?)` 重载的 format 字符串
  解析（C# 版为手写解析）列入对拍项。

### 6.2 方法清单与委托关系

**改写器调用闭集（验收基线）**：

- 算术/位运算（Int32 域一律内联、不产生调用）：`Add`/`Subtract`/
  `Multiply`/`Divide`/`Remainder`/`And`/`Or`/`Xor` × {`Int64`, `UInt32`,
  `UInt64`}
- 一元取反：`NotUInt32`、`NotUInt64`
- 比较：`CompareInt64`、`CompareUInt32`、`CompareUInt64`
- 自增/自减：复用 `Add`/`Subtract`{`UInt32`,`UInt64`}`(x, 1)`
- 转换：`ToByteInt32`、`ToByteInt64`、`ToUInt16Int32`、`ToUInt16Int64`、
  `ToInt32UInt64`、`ToInt64UInt32`、`ToUInt64UInt32`、`ToDoubleUInt32`、
  `ToDoubleUInt64`、`ToSingleUInt32`、`ToSingleUInt64`、`ToDecimalUInt32`、
  `ToDecimalUInt64`
- ToString：`ToStringUInt32`/`ToStringUInt64` 各 4 个重载：
  `(v)`、`(v, string?)`、`(v, IFormatProvider?)`、`(v, string?, IFormatProvider?)`
- 移位：**全部内联**（`<<`、`>>>`），`LeftShift*`/`RightShift*` 不在调用
  闭集（全集口径下仍实现，仅供对称）。

**Java 实现委托关系**（全集口径）：

| 方法组 | Java 实现 |
| --- | --- |
| Add/Subtract/Multiply/And/Or/Xor（Int64/UInt32/UInt64 域） | 原生 long/int 运算（补码回绕与 C# `unchecked` 一致） |
| Divide/Remainder UInt32 | `Integer.divideUnsigned` / `Integer.remainderUnsigned` |
| Divide/Remainder UInt64 | `Long.divideUnsigned` / `Long.remainderUnsigned` |
| NotUInt32 / NotUInt64 | `~`（原生补码取反） |
| CompareInt64 | `Long.compare` |
| CompareUInt32 / CompareUInt64 | `Integer.compareUnsigned` / `Long.compareUnsigned` |
| LeftShift*/RightShift*（闭集外） | `<<` / `>>>` 直写 |
| ToInt64UInt32 / ToUInt64UInt32 | `(long)(v & 0xFFFFFFFFL)` / `v & 0xFFFFFFFFL` |
| 其余转换（ToByte*/ToUInt16*/ToInt32UInt64/ToDouble*/ToSingle*/ToDecimal*） | 与 C# 版逐方法对齐（掩码/截断/经 `toUnsignedString`+Parse 同路直译），以 `UnsignedMathFileContent.cs` 现实现为蓝本逐一翻译 |
| ToStringUInt32/64 各重载 | `Integer/Long.toUnsignedString`；带 provider 重载恒 InvariantCulture（与 C# 版一致），format 解析对拍 |

### 6.3 TypeMappings

- `config/TypeMappings.json` 增加类型级映射：
  `Cs2jUnsigned.UnsignedMath → io.github.ningpp.compat.UnsignedMath`。
- 匹配语义：`csharp` 键按 C# 侧全限定名精确匹配
  （`TypeMappingService` 以 `ToDisplayString(FullyQualifiedFormat)` 构造键）；
  `Cs2jUnsigned.UnsignedMath` 为顶级类，与既有
  `System.Text.Json.JsonSerializer` 条目同形态，可直接命中。
- 方法名透传论证（无需方法条目）：`MapMethod` 用 C# 侧原始类型名查询；
  `Cs2jUnsigned.UnsignedMath` 不在 `config/java/` JDK 索引中，
  `ResolveJavaCanonicalName` 返回 null，Pascal→camel 自动推导不触发，
  方法名按 C# 原名透传——恰与 compat 手写类的同名方法匹配。若端到端
  测试发现某调用形态未被路由，按闭集补 `(type, method, paramCount)`
  显式条目。
- 转换后的调用点形态：import `io.github.ningpp.compat.UnsignedMath`，
  调用 `UnsignedMath.XXX(...)`；import 注入由条目 `imports` 字段驱动，
  以端到端测试验证。

## 7. 语义一致性

C# 版 helper 本就是 JDK unsigned API 的忠实移植（有
`UnsignedTypeSemanticsTests` 逐字节输出比对背书）；Java 手写版直接调 JDK，
两者对齐由 compat 新增 JUnit 单测保证：对每个闭集方法在边界值
（0、1、MaxValue、MinValue 位模式、MaxValue/2、随机值）上与 JDK 参考行为
对拍，format/provider 重载按 §6.1 对拍项执行。

## 9. 已知限制与风险

- **TypeMappings 覆盖面**：调用形态是改写器生成的封闭集合
  （全限定静态调用、无 using、无扩展接收者、无泛型），且 §6.3 已给出
  方法名透传的机制论证；残余风险由端到端测试兜底，发现缺口按闭集补条目。
- **TFM**：`Cs2jUnsignedMath` 为 net10.0，宿主项目目标低于 net10.0 时
  引用失败，表现为 NU1201 不兼容框架错误（net8.0/net9.0/netstandard2.0
  host 同理）。处理策略：预处理阶段读取 host TFM，低于 net10.0 时在
  **构建前告警**（附 NU1201 表现与两条出路：升级宿主 TFM / 再议
  `Cs2jUnsignedMath` 多目标），而非等用户 `dotnet build` 中间树时才失败。
  多目标的触发条件即"预处理告警后仍有用户报告 NU1201"。
- **名称碰撞**：释放入口 fail-fast 检测（§5.1），用户 sln 已含
  `Cs2jUnsignedMath.csproj` 即报错终止；契约见 2026-08-15 文档 §4.3。
- **阶段复制**：已核实成立（逐文件全树复制，未变更文件也复制），
  不再列为风险；附带验证项见 §5.1（csproj 重写 no-op、obj/bin 冗余）。
- **workspace 符号可见性**：见 §5.2 前置验证；fallback 为显式补载。

## 10. 迁移

- 需要重新构建并安装 compat：
  `mvn install -f java/csharptojava-compat/pom.xml`
  （坐标 `io.github.ningpp:csharptojava-compat:1.0-SNAPSHOT`；生成模块
  pom 对该 SNAPSHOT 的解析走本地仓库，本机为 `D:\mvnrepo`，非默认
  `~/.m2/repository`）。
- 旧产物需重跑 cs2j 全流水线再生效；旧模块中的
  `Cs2jUnsigned/UnsignedMath.java` 不会被自动清理（与新 compat 类不同包、
