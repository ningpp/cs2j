## Plan: 系统性问题分析文档

对整个 cs2j 项目进行了四轮深入探索（Transformer 层、类型映射系统、测试与已知问题、语义模型与泛型），编写一份全面的问题分析文档 `docs/systematic-issues-analysis.md`，涵盖以下 11 个模块。

**Steps**

### 阶段一：核心正确性问题（Critical）

1. **语义模型空值退化** — `ConversionContext.SemanticModel` 可为 null，`TypeMappingService` 在语义信息缺失时静默退化为 `Object` 或原始类型名。`IErrorTypeSymbol` 处理只取语法名称不取完整限定名，导致跨命名空间类型碰撞。需在 ConversionContext.cs 和 TypeMappingService.cs 中增加诊断。

2. **泛型嵌套映射不递归** — `MapTypeForGeneric()` 仅做基本类型装箱（int→Integer），不递归映射嵌套泛型（如 `Dictionary<string, List<Tuple<int, string>>>`）。影响 TypeMappingService.cs 的 `MapType` 系列方法。

3. **泛型约束丢失** — `where T : new()` 静默丢弃（DelegateTransformer.cs），`where T : struct/unmanaged` 无处理。协变/逆变（`in`/`out`）完全忽略。

4. **类型擦除冲突不完整** — 仅检测方法级冲突（ClassTransformer.cs），不检测字段、嵌套类型、跨继承链擦除冲突。

5. **方法重载解析不精确** — 方法映射基于名称无参数签名匹配（如 `String.Substring` 两个重载映射到同一 `substring`），TypeMappingRegistry.cs 无重载区分机制。

### 阶段二：语言特性覆盖缺口（High）

6. **模式匹配严重不足** — 仅支持类型模式和简单 is/not/and/or 模式；递归模式、属性模式、列表模式、位置模式均回退为 TODO 注释或原始 C# 文本。

7. **元组支持不完整** — 统一转为 `new Object[]{...}` 占位，无类型安全的解构。`var (a, b) = ...` 解构赋值未实现。

8. **Span/Memory/stackalloc 无等价映射** — `Span<T>`, `ReadOnlySpan<T>`, `Memory<T>` 保留为原始类型名，`stackalloc` 降级为堆分配。

9. **异步迭代器未支持** — `IAsyncEnumerable<T>`, `await foreach` 无转换逻辑。

10. **C# 11/12 新特性空白** — `required` 成员、`static abstract/virtual` 接口成员、字符串插值处理器、集合表达式 spread 语法均无处理。

11. **可空引用类型（NRT）忽略** — `#nullable enable` 指令被忽略，`T?` 注解不保留，null-forgiving `!` 操作符被剥离。

### 阶段三：跨文件/跨项目问题（High）

12. **无前向引用排序** — ProjectConversionPipeline.cs 无类型依赖拓扑排序，Java 要求先声明后使用。

13. **循环依赖无检测** — 跨项目循环引用无检测、无断环策略、无诊断输出。

14. **跨包导入暴力通配** — CrossPackageImportResolver.cs 为每个结果添加所有包的通配符导入，规模复杂度 O(N²)，多包同名类导致歧义。

15. **跨程序集引用无验证** — 传递依赖不验证是否完整加载，缺失引用导致级联类型损坏。

### 阶段四：代码生成与 IR 质量（Medium）

16. **JavaRaw 回退过度使用** — 约 20+ 处生成 `JavaRawExpression`/`JavaRawStatement`，这些节点对验证 rewriter 不可见（变量声明、作用域追踪失效）。

17. **LINQ 转换不完整** — Join/GroupJoin 未实现，`orderby` 静默忽略，`Union/Intersect/Except` 被 yield return 要求阻塞。

18. **原始流 API 生成错误** — 原始类型数组（`int[]`, `double[]`）在某些情况下生成不存在的 `mapToDouble` identity 包装。

19. **不支持的构造静默降级** — `fixed`/`unsafe` 语句、P/Invoke 仅生成 TODO 注释或 `UnsupportedOperationException`，无编译期拦截。

### 阶段五：类型映射缺口（Medium）

20. **大量 BCL 子系统未映射** — `System.Reflection.Emit`（20+ 类型）、`System.IO.Compression`（8 类型）、`System.Security.Cryptography`（15+ 类型）、`System.Collections.Immutable`（18 类型）、`System.Diagnostics`（10+ 类型）完全缺失。

21. **命名空间映射冲突** — `System.ComponentModel` → `javafx.beans`（仅适用 GUI）、`System.Collections.ObjectModel` 与 `System.Collections.Generic` 共享 `java.util`（名称碰撞）。

### 阶段六：质量保障机制（Medium-Low）

22. **无转换质量评分** — `ConversionResult.Success` 仅有 bool 值，无 TODO 计数、raw 回退比例、类型解析失败率等指标。

23. **验证仅覆盖结构化 IR** — 21 个 Rewriter 无法检查 `JavaRawStatement` 内的变量引用和类型使用。

24. **注释保留不完整** — 表达式内 inline 注释丢失，XML 文档标签仅覆盖 `<summary>`/`<param>`/`<returns>`，缺少 `<exception>`、`<remarks>`、`<typeparam>`。

**Relevant files**
- ConversionContext.cs — 语义模型管理，类型栈
- TypeMappingService.cs — 类型映射核心逻辑
- TypeMappingRegistry.cs — 配置驱动的映射注册
- TypeMappings.json — 680+ 类型映射配置
- Transformers — 所有 Transformer 实现
- ProjectConversionPipeline.cs — 项目级 11-pass 管线
- Java — Java IR 定义与 21 个 Rewriter
- LinqRewrite — LINQ 重写引擎

**Verification**
1. 运行 `dotnet test` 确认所有现有测试通过
2. 文档完成后可用于指导后续修复工作的优先级

**Decisions**
- 文档目标路径: `docs/systematic-issues-analysis.md`
- 按正确性影响分 P0/P1/P2/P3 四级优先级
- 每个问题给出具体代码位置引用
- 面向 Roslyn 2.x/3.x 规模项目进行影响评估

**Further Considerations**
1. 某些问题（Span/Memory、Reflection.Emit、Source Generator）可能需要标记为"人工介入"而非自动转换，文档中应明确区分"可修复"和"架构限制"
2. 类型映射缺口可通过扩展 TypeMappings.json 解决，但方法映射的重载精度是架构问题需要代码层面修改
