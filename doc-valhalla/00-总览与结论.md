# Project Valhalla 与无符号类型/Float16 — 总览与结论

> 调研日期: 2026-06-20
> 调研目的: 判断 Java (OpenJDK Valhalla) 后续是否会支持 C# 的无符号 byte/ushort/uint/ulong 以及 float16

---

## 核心结论

### 1. 无符号整数类型 (ubyte/ushort/uint/ulong) — Java 不会直接内置，但 Valhalla 使之成为可能的库类型

**关键发现:**
- Valhalla 的设计文档中**明确提到了 `UnsignedShort` 作为 primitive class 的示例**
- Brian Goetz 在 "State of Valhalla Part 2" 中写道: *"there are infinitely many numeric types we might want to add to Java, but the proper way to do that is as **libraries, not as language features**"*
- Java 的哲学是: 通过 Valhalla 的 primitive class 机制，让用户**自行定义**无符号类型，而非在语言中内置

**示例 (来自 Valhalla 设计文档):**
```java
primitive UnsignedShort extends Number
                        implements Comparable<UnsignedShort> {
   ...
}
```

**影响评估:**
- 不会像 C# 那样有 `uint`, `ulong` 等关键字
- 但 Valhalla 完成后，可以创建性能等同于内置原始类型的无符号类型库
- 这些自定义 primitive class 将拥有: 扁平内存布局、无装箱开销、可泛型化

### 2. Float16 (半精度浮点) — 已有明确规划，将作为 value class 支持

**关键发现:**
- **JEP 469 (Vector API)** 明确提到: *"We may add support for vectors of IEEE floating-point binary16 values (float16) ... represent a float16 value as a **value object**, with optimized layout in arrays"*
- Float16 被定位为 Valhalla 的 value class，而非语言内置原始类型
- Vector API 的未来版本将支持 float16 向量运算，利用硬件 SIMD 指令

**影响评估:**
- Float16 将以 `value class` (或 `primitive class`) 形式出现
- 可能首先在 Vector API 中作为 incubator 模块出现
- 需要等待 Valhalla 的 value class 特性稳定后才能正式化

### 3. 对 cs2j 转换器的建议

| C# 类型 | Java 当前方案 | Valhalla 后的方案 |
|---------|-------------|-----------------|
| `byte` (无符号) | `short` 或 `Byte.toUnsignedInt()` | `primitive UnsignedByte` (库) |
| `ushort` | `int` 或 `Short.toUnsignedInt()` | `primitive UnsignedShort` (库) |
| `uint` | `long` 或 `Integer.toUnsignedLong()` | `primitive UnsignedInt` (库) |
| `ulong` | `BigInteger` | `primitive UnsignedLong` (库) |
| `Half` (float16) | 无直接支持 | `value class Float16` (库) |

## Valhalla 时间线估计

| 阶段 | 特性 | 预计 Java 版本 |
|------|------|---------------|
| Phase 1 | Value Classes and Objects (JEP 401) | Java 25 Preview → 已可用 |
| Phase 1 | Null-Restricted Value Class Types | Draft (更新于 2026/05) |
| Phase 1 | Enhanced Primitive Boxing (JEP 402) | Draft |
| Phase 2 | Primitive Classes | 未来版本 (可能 Java 27+) |
| Phase 2 | Migrating existing primitives (int→primitive class) | 远期 |
| Phase 3 | Specialized Generics | 远期 |

**关键时间点:**
- JEP 401 (Value Classes) 已经是 Submitted 状态，更新于 2026/06/17
- JEP 402 (Enhanced Primitive Boxing) 是 Draft 状态
- Primitive Classes 尚无确定的 JEP 编号
- 完全的无符号类型支持需要 Phase 2 完成，估计至少还需要 2-3 年
