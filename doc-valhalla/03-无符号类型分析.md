# 无符号类型在 Java/Valhalla 中的分析

---

## C# 的无符号类型

C# 提供以下无符号整数类型:

| C# 类型 | 大小 | 范围 | .NET 类型 |
|---------|------|------|----------|
| `byte` | 8-bit | 0 到 255 | `System.Byte` |
| `ushort` | 16-bit | 0 到 65,535 | `System.UInt16` |
| `uint` | 32-bit | 0 到 4,294,967,295 | `System.UInt32` |
| `ulong` | 64-bit | 0 到 18,446,744,073,709,551,615 | `System.UInt64` |

这些是**语言内置类型**，有完整的运算符支持、字面量语法、溢出检查等。

---

## Java 当前的无符号支持

### 现状
Java **没有**无符号原始类型。所有整数类型都是有符号的:
- `byte`: -128 到 127
- `short`: -32,768 到 32,767
- `int`: -2^31 到 2^31-1
- `long`: -2^63 到 2^63-1

### Java 8+ 的无符号工具方法

Java 8 引入了一些无符号操作的工具方法:

```java
// Integer 类
Integer.toUnsignedString(int i)
Integer.parseUnsignedInt(String s)
Integer.compareUnsigned(int x, int y)
Integer.divideUnsigned(int dividend, int divisor)
Integer.remainderUnsigned(int dividend, int divisor)
Integer.toUnsignedLong(int x)  // 将 int 零扩展为 long

// Long 类
Long.toUnsignedString(long i)
Long.parseUnsignedLong(String s)
Long.compareUnsigned(long x, long y)
Long.divideUnsigned(long dividend, long divisor)
Long.remainderUnsigned(long dividend, long divisor)
Long.toUnsignedString(long i, int radix)
```

### 当前转换策略

对于 cs2j 转换器，当前的映射策略:

| C# 类型 | Java 映射 | 问题 |
|---------|----------|------|
| `byte` (0-255) | `short` | 浪费空间，破坏数组布局 |
| `ushort` (0-65535) | `int` | 浪费空间 |
| `uint` (0-2^32-1) | `long` | 浪费空间，无法用于泛型 |
| `ulong` (0-2^64-1) | `BigInteger` | 性能差，API 不兼容 |

## Valhalla 的解决方案: Primitive Classes

### 设计文档中的明确示例

State of Valhalla Part 2 (Brian Goetz, 2021) 中**明确**给出了 `UnsignedShort` 作为 primitive class 的示例:

```java
primitive UnsignedShort extends Number
                        implements Comparable<UnsignedShort> {
   // 字段、构造函数、方法...
}
```

### Primitive Class 的特性

一个 primitive class:
1. **有方法和构造函数** (不同于现有原始类型)
2. **不能为 null** (非空类型)
3. **默认值是零实例** (所有字段为默认值)
4. **可被撕裂 (tearing)** (在数据竞争下，类似 `long`/`double`)
5. **有两种类型**: 原始类型 (`UnsignedShort`) 和引用类型 (`UnsignedShort.ref`)
6. **可继承和实现接口**: `UnsignedShort.ref <: Number`

### 内存布局优势

```java
// Valhalla 之前
List<UnsignedShort> list = ...;  // 不可能，UnsignedShort 不是类型
// 只能用 List<Integer> 然后手动处理

// Valhalla 之后
primitive UnsignedShort { ... }

// 数组是扁平的，无指针间接引用
UnsignedShort[] array = new UnsignedShort[1000];
// 内存布局: [us1][us2][us3]...  直接存储值，无对象头

// 可以泛型化
List<UnsignedShort> list = ...;  // Phase 3 完全支持
```

### 使用示例

```java
primitive UnsignedShort extends Number
                        implements Comparable<UnsignedShort> {
    private final short value;

    // 私有构造函数，使用工厂方法
    private UnsignedShort(short value) {
        this.value = value;
    }

    // 工厂方法
    public static UnsignedShort of(short value) {
        if (value < 0) throw new IllegalArgumentException();
        return new UnsignedShort(value);
    }

    // 值获取
    public int intValue() { return Short.toUnsignedInt(value); }
    public long longValue() { return Integer.toUnsignedLong(intValue()); }

    // 算术运算
    public UnsignedShort add(UnsignedShort other) {
        return new UnsignedShort((short)(this.value + other.value));
    }

    // 比较
    @Override
    public int compareTo(UnsignedShort other) {
        return Integer.compare(this.intValue(), other.intValue());
    }

    // ...
}

// 使用
UnsignedShort us = UnsignedShort.of(60000);
UnsignedShort us2 = us.add(UnsignedShort.of(5000));

// 可以作为 Number 使用
Number n = us;  // 自动转换为 UnsignedShort.ref

// 数组扁平化
UnsignedShort[] array = new UnsignedShort[1000];
// 直接存储，无对象头，无指针
```

## 无符号类型需要的完整功能集

要完全替代 C# 的无符号类型，Valhalla 需要:

### 已有/即将有
- [x] Value Classes (JEP 401) — 已 Submitted
- [ ] Primitive Classes — 设计阶段
- [ ] 泛型支持 — Phase 3

### 缺失的功能
1. **字面量语法**: C# 有 `42u`, `42UL`，Java 没有无符号字面量
2. **运算符重载**: C# 的无符号类型有完整的算术运算符，Java primitive class 需要定义方法
3. **溢出检查**: C# 有 `checked`/`unchecked`，Java 需要手动处理
4. **与有符号类型的隐式转换**: C# 允许 `uint` 到 `ulong` 的隐式转换
5. **标准库集成**: 需要 `java.util` 等核心库支持

### 预期的 Java 使用模式

```java
// 假设 Valhalla Phase 2 完成后的使用方式

// 定义 (可能由 JDK 或第三方库提供)
primitive uint { ... }
primitive ulong { ... }

// 使用 (类似 C# 但语法不同)
uint x = 42;  // 可能需要特殊语法或工厂方法
uint y = x + 10;  // 需要运算符支持 (Valhalla 未来可能支持)
ulong z = x.toUnsignedLong();

// 泛型 (Phase 3)
List<uint> list = new ArrayList<>();
list.add(42);
```

## 时间线评估

| 特性 | 预计可用时间 | 对 cs2j 的影响 |
|------|-------------|---------------|
| Value Classes (JEP 401) | Java 25 Preview | 低 — 不直接影响无符号类型 |
| Primitive Classes | Java 27+ (估计) | 高 — 使自定义无符号类型成为可能 |
| 泛型原始类型支持 | Java 28+ (估计) | 高 — 允许 `List<uint>` |
| 运算符重载 | 未确定 | 中 — 改善使用体验 |
| 完整的无符号类型库 | Java 29+ (估计) | 高 — 提供标准实现 |

**总结**: 完全的无符号类型支持 (类似 C# 的体验) 预计至少还需要 **3-5 年**。

## 对 cs2j 转换器的当前建议

在 Valhalla 完全成熟之前，建议:

1. **保持当前映射策略**: `byte→short`, `ushort→int`, `uint→long`, `ulong→BigInteger`
2. **添加注释**: 在生成的 Java 代码中添加注释，说明原始 C# 类型
3. **提供工具类**: 生成辅助方法进行无符号操作
4. **监控 Valhalla 进展**: 特别关注 Primitive Classes 的 JEP

```java
// 生成的 Java 代码示例
/**
 * C# original: uint count
 * Java mapping: long count (unsigned 32-bit)
 * Note: Use Integer.toUnsignedInt() for correct unsigned interpretation
 */
long count = 0;

// 辅助方法
public static long uintAdd(long a, long b) {
    return Integer.toUnsignedLong(Integer.sum(
        Integer.parseUnsignedInt(Long.toUnsignedString(a)),
        Integer.parseUnsignedInt(Long.toUnsignedString(b))
    ));
}
```
